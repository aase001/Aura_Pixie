# Aura Pixie

> 桌面径向菜单（Radial Menu）+ 快捷指令启动器 + 资源监视小工具
>
> 常驻透明呼吸圆球，悬停展开扇形菜单，一键执行你的常用指令；可选磁吸迷你窗格实时监视 CPU / GPU / 内存 / 硬盘 / 网络。轻量、静默、单文件分发。

## 简介

Aura Pixie 是一个驻留在桌面任意位置的呼吸光效圆球小助手：

* 平时是一个透明呼吸的小球，不遮挡视线、不进任务栏；
* 鼠标悬停在球上约 1000ms，圆环扇形菜单自动展开，展示你设置的功能模块（2~9 个）；
* 单击无标记扇区立即执行对应指令（打开应用、运行脚本、执行命令），执行后自动收起复位；
* 单击挂了子功能的扇区展开二级环形菜单，双击则直达主指令；
* 球体可以拖动、贴边吸附，位置自动记忆，下次启动原样恢复；
* 右键打开「监视」，可勾选任意硬件参数，每个参数一个磁吸迷你窗格，数值 + 曲线实时刷新。

它适合把高频操作收拢到一个「触手可及」的入口：重点是它好看又好用。

## 功能特性

### 球体与扇形

* 常驻呼吸球体：透明无边框、可置顶（可选）、可锁定（禁拖动）、不进任务栏；无描边、光晕虚化过渡
* 悬停展开动态扇形：累计悬停 1000ms 展开、离开 180ms 收起，等分数 = 激活功能数（2~9，超出取前 9）
* 单击执行 + 闪光反馈：成功白闪 220ms / 失败红闪 420ms，静默执行、自动复位
* 次级动态扇形：「成对特殊标记」挂载子功能，单击扇区展开次级环（一个功能可挂 2~9 个次级指令），双击执行主指令
* 三种指令格式：`python 代码` / `cmd 命令` / `powershell 5.1~7.x`，支持多行编写，一切静默无黑窗
* 指令高级编辑窗：右键指令单元格 →「高级编辑…」，独立大窗口编写，内置「测试 / 保存 / 取消」（⚠ 测试会真实执行指令，窗口内有醒目警示）
* 内置动作：指令写 `monitor:` 前缀 = 点击扇区直接打开监视设置窗
* 球体拖动 + 屏幕吸附：弹簧非线性跟随，外缘距屏幕边缘 ≤200px 松手自动吸附，越界红虚线闪烁回弹
* 动效休眠：无交互到达设定秒数 → 呼吸暂停、透明度降至休眠值，并随系统深浅色顺色保持可见；点击唤起；倒计时可选「永不」

### 外观与主题

* 球体呼吸开关（关闭 = 颜色与大小全停）、起始/过渡/末尾三色（十六进制 + 系统取色）、三段渐变时长（1~30s）、呼吸倍率（0.1x~3x）
* 滑块化参数：球体透明度（10~100%）、休眠透明度（5~20%）、休眠倒计时（30~600s + 永不）、资源监视透明度（10~100%）
* 资源监视窗口色 + 底色填充开关：取消填充 = 窗格底色与光晕全透明，只留文字与曲线
* 显示缩放：球体及扇形 / 资源监视 / 快捷启动（预留）三个单元，各自 50%~200%（每阶 25%）
* 全窗口跟随系统深浅色：设置/外观/监视/帮助窗调色板 + 标题栏统一主题，运行中切换系统主题即时刷新

### 资源监视

* 一参数一窗格：每个勾选的参数一个独立迷你窗（固定 250×80px，标签超宽时全体统一扩至 350px）
* 指标覆盖：CPU 利用/频率/温度/功耗、内存利用/用量、核显利用/共享内存、独显利用/温度/功耗/显存（多卡全量枚举）、网络收发速率、硬盘温度/占用空间、风扇转速（视硬件支持）
* 曲线：底部锚定 30px 曲线区，约 1 分钟历史；纵坐标按当前值所在档位即时读取；绿/黄/红固定段色 + 曲线下方渐变填充；部分波动极小的指标不画曲线（可配置排除清单）
* 用量类指标按「用量 ÷ 总量」百分比定绿黄红（0~60 / 60~85 / 85~100）
* 磁吸成组：窗间/屏幕边磁吸，移动中幽灵虚线预览、松手吸附对齐；整组刚性移动、多对多合并；右键拖动解绑
* 窗口置顶 / 锁定：与球体置顶完全解耦；锁定后窗格禁移动、禁拆分/合并组，交互照常
* 布局持久化：位置与组合自动记忆，退出/关机立即落盘，重启自动恢复
* 采样 1s/拍；关窗不停采、重开秒回；全部窗格关闭闲置超时才停采释放

### 系统集成

* 单实例 + 定位：全局仅一个实例；二次启动弹「本球在此」，可一键「在哪儿？」让运行中的球体红框闪烁定位
* 开机自启（可选）：任务计划程序（登录触发 + 最高权限），打包形态启动自愈
* 管理员运行：资源监视温度/功耗/硬盘类读数依赖内核驱动，启动自动 UAC 提权；调试可用 `--no-elevate` 免提权（温度类指标不可用）
* 位置记忆：球体移动停止 10 秒自动落盘，强杀/断电位置也不丢；无记录默认屏幕右侧中间贴边
* 统一配置根目录：`%LOCALAPPDATA%\Aura_Pixie\`，按写入方拆成四文件——`config.yaml`（数值调参）/ `command.yaml`（功能指令）/ `setting.yaml`（外观偏好与开关）/ `state.yaml`（坐标与布局，程序自动写）；另有首启释放的 `README.md` 与异常日志 `crash.log`
* 配置导入/导出：一键备份到任意文件夹、导入合并（内容合法性校验）
* 单文件分发：图标、采集侧车、中文翻译全部内嵌，无需安装依赖

## 使用说明

### 球体交互

| 操作 | 行为 |
| ------------ | ------------------------ |
| 悬停（约 1000ms） | 展开扇形菜单，等分为激活功能数 |
| 悬停移动 | 高亮跟随光标所在扇区 |
| 单击扇区（无标记） | 立即执行：闪光反馈 → 静默执行指令 → 收起复位 |
| 单击扇区（含标记） | 登记待展开 → 约 330ms 确认后收起主环、展开次级动态扇形 |
| 双击扇区（含标记） | 取消展开、立即执行主指令（主指令为空则仅收起不执行） |
| 次级环上单击 | 直接执行该次级项（不递归） |
| 按住拖动 | 移动球体（光标变为四向移动箭头）；外缘距屏边 ≤200px 松手自动吸附；「锁定」开启时禁拖动 |
| 右键球体/环外 | 打开默认菜单（设置 / 监视 / 重载 / 消失 / 退出），右键时先收起扇形 |
| 点击休眠球 | 唤醒并恢复正常透明度 |

### 设置界面

设置窗为三列表格 + 底部按钮行（外观 / 监视 / 导入导出配置 / 保存 / 取消），「帮助」按钮在顶部：

* 激活：居中复选框，勾选后该功能计入扇形等分数（2~9）；
* 功能：扇形上显示的名称（≤6 汉字 / 12 字母）；
* 指令：双击 = 行内多行编辑；右键 → 高级编辑… = 独立大窗口（推荐编写复杂/多行指令）；
* 拖动整行可调整功能顺序（保存后即时生效，勾选态随行走）；
* 「开机自启动」勾选即时生效（注册计划任务并校验实况）。

### 外观窗

* 首行：球体呼吸 / 保持球体置顶 / 锁定（三个开关同一行）；
* 滑块顺序：呼吸倍率 → 球体透明度 → 休眠透明度 → 休眠倒计时（末档「永不」）；
* 分割线下方：资源监视窗口色（标题前有底色填充复选框）→ 资源监视透明度 → 显示缩放；
* 呼吸关闭时颜色/时长/倍率整组置灰；「永不」时休眠透明度置灰；窗口高度随内容自适应。

### 监视设置窗

右键球体 →「监视」（或设置窗底部「监视」按钮）：

* 首行：「启用资源监视」总开关 + 「窗口置顶」+ 「锁定」+ 「全选/全不选」；
* 参数按 CPU / 内存 / GPU 核显 / GPU 独显 / 硬盘 / 风扇 / 网络分组罗列，有设备名的参数右侧同一行显示设备名小字；
* 勾选参数实时建窗、取消实时关窗；打开设置窗即轻量预览采集以显示设备名；
* 「重置」= 全不选 + 清位置记忆 + 窗格解散归零（总开关不动）；
* 窗格右键「关闭本窗」会同步取消设置里的勾选。

### 指令格式

指令默认按 Python 处理；以格式名前缀开头可切换执行环境：

```
cmd: start notepad                     # CMD：打开记事本
ps: Start-Process notepad              # PowerShell 5.1
pwsh: Write-Host "hi"                  # PowerShell 7（无则回退 5.1）
py: import subprocess; subprocess.Popen(['notepad.exe'])   # Python（默认）
monitor:                               # 内置动作：打开监视设置窗
```

多行写法：第一行写 `格式名:`，指令内容从第二行开始（也可以与格式名同行）。

* `cmd` 多行会逐行依次执行，自动用 `&` 连接，每行独立、不要缩进；
* `ps/pwsh` 多行按换行连接执行，块内语句保持缩进、顶层顶格；
* `py` 多行即完整 Python 程序，保留换行与缩进，块内 4 空格、顶层顶格。

所有指令静默执行（`CREATE_NO_WINDOW`，不会弹黑色控制台窗口）；程序只负责启动指令，不等待运行结束，UI 不卡顿。

### 指令高级编辑窗

在设置窗「指令」列单元格上右键 → 高级编辑…：

| 按钮 | 行为 |
| ------ | ------ |
| 测试 | 按扇区点击完全一致的逻辑真实执行当前指令（可能启动程序、修改文件或联网，窗口内有醒目警示），输出/退出码/错误信息显示在结果区；含成对标记时只测主指令；超时（15s）停止轮询，进程后台自行结束 |
| 保存 | 仅校验格式/语法是否合法，不执行；非法弹窗提示并留在编辑窗，合法写回单元格 |
| 取消 | 不做任何更改，直接返回设置界面 |

### 次级动态扇形（成对特殊标记）

在指令中加入「成对特殊标记」可为该扇区挂载多个次级子功能（单击展开）：

```
【【【子功能名】】】
子功能指令（cmd/ps/pwsh/py 均可，多行）
【【【子功能名】】】
```

* 第一个标记之前的内容 = 主指令：双击该扇区执行主指令（可为空，为空则仅收起不执行、不闪红）；
* 每对同名标记之间 = 一个次级项指令，一个功能可定义 **2~9 个**；单击扇区 → 约 330ms 确认 → 收起 300ms → 展开次级环形菜单；
* 标记必须成对闭合（`【【【名称】】】` 配对包裹，栈式同名配对），不支持嵌套，保存时校验闭合与数量；
* 次级环上的扇区单击直接执行该项、不再嵌套（不递归）。

## 资源监视

### 指标一览

| 分组 | 指标 | 单位 | 数据源与条件 |
| --- | --- | --- | --- |
| CPU | CPU利用 / CPU频率 / CPU温度 / CPU功耗 | % / GHz / ℃ / W | psutil；温度/功耗需管理员 + 驱动支持 |
| 内存 | 内存利用 / 内存用量 | % / GB | psutil |
| GPU 核显 | GPU利用 / 共享内存用量 | % / GB | 侧车 D3D 计数器 |
| GPU 独显（每卡 5 项） | GPU利用 / GPU温度 / GPU功耗 / GPU显存利用 / GPU显存用量 | % / ℃ / W / % / GB | 侧车全量枚举，多卡各自展开 |
| 网络 | 网络发送速率 / 网络接收速率 | MB/s（<1MB/s 自动切 KB/s） | psutil 差分 |
| 硬盘（每盘 2 项） | 硬盘温度 / 硬盘占用空间 | ℃ / % | 侧车温度 / 容量占比 |
| 风扇 | ×风扇转速 | RPM | 侧车；部分笔记本 EC 不暴露，无读数属正常 |

温度/功耗/硬盘类读数依赖管理员权限与内核驱动（LibreHardwareMonitorLib + PawnIO）；非管理员运行时这些参数标「需要管理员」，其余参数照常。

### 窗格与曲线

* 固定基准 250×80px（×显示缩放），任一窗格标签自然宽超基准 → 全体统一扩到 350px（只升不降）；
* 三列布局「名称 | 数值 | 单位」，15px 加粗字体；名称/单位/硬件名小字按窗口色亮度自动黑/白字；
* 数值与曲线按阈值着语义色：绿 `#3FB950` / 黄 `#D29922` / 红 `#F85149`，段内恒定不渐变；进最高档 1Hz 呼吸闪烁；
* 曲线区底部锚定、高 30px（×缩放），约 60 点 ≈ 1 分钟历史；纵坐标按当前值所在档即时取区间（绿档 [0, 绿上界]、黄档 [绿上界, 黄上界]、红档 [绿上界, 红上界]），跨档瞬间整体切换；网络速率保留动态 min/max；
* 曲线下方用当前色向全透明渐变填充；以下指标不画曲线（数据照常记录）：硬盘占用空间、硬盘温度、共享内存用量、GPU显存用量、GPU显存利用、内存利用、内存用量；
* 用量类（内存用量/共享内存/显存用量）按占总量百分比定色，总量缺失时中性灰；
* 窗口色可配（默认 `#181A20`），填充 + 边缘光晕同色；取消「底色填充」= 底色与光晕全透明，字色仍按窗口色亮度判定；
* 资源监视透明度作用于窗格整体（文字/曲线/光晕一起变透），与球体透明度互不影响。

### 磁吸与布局

* 左键拖动即时跟手；靠近其它窗格/组（<20px）出现幽灵虚线预览，松手平滑吸附：左右贴 → 顶边对齐，上下贴 → 左缘对齐；
* 单对单 / 单对多 / 多对单 / 多对多均正确合并为一个组，整组刚性移动；屏幕边整组贴边；
* 右键拖动 >4px 解绑自身（锁定态不解绑）；右键轻点弹菜单（关闭本窗等）；
* 无记忆位置的窗格统一在球体左边重叠显示，由用户手动拖开；有记忆位按记忆恢复；
* 位置与组合记忆多屏合法性校验；退出/关机立即落盘 + 静止快速落盘双保险，重启自动恢复窗格与组；
* 「锁定」开启：窗格禁移动、禁拆分/合并组，已成组保持原组，右键菜单/数值刷新照常。

## 配置说明

配置根目录：`%LOCALAPPDATA%\Aura_Pixie\`。v2.03 起按**写入方**拆成四个文件，各管一块，互不干扰：

| 文件 | 内容 | 谁在写 |
| --- | --- | --- |
| `config.yaml` | 全软件数值调参（球体交互 / 监视窗格 / 采集层），总开关 `enabled` 默认 `false` | 你手改；程序只读 |
| `command.yaml` | `functions` 功能扇区列表 | 「设置」窗保存 |
| `setting.yaml` | `appearance` 外观 / `autostart` 自启 / `window` 开关 / `monitor` 开关与 units | 「外观」「监视」窗保存 |
| `state.yaml` | 球心坐标 `window.pos_x/pos_y` + `monitor.layout` 窗格布局 | 程序自动写（勿手改） |

另有首启释放的 `README.md`（参数逐项中文说明）、`crash.log`（异常日志，超 1MB 轮转保留一代 `crash.old.log`）、`backup\`（迁移/导入前快照，保留最近 5 份）、`command\`（执行脚本缓存，哈希命名复用；`test\` 子目录放测试产物）。

**数值调参（config.yaml）**：出厂 `enabled: false` = 安全模式，改任何数值都不生效；改成 `true` 后数值才生效（逐键钳制，非法值回退默认），改完须在球体上**右键「重载」**——程序不监听文件。完整键表与每项的【作用范围】【影响】【取值范围】见配置目录里的 `README.md`。

**四个文件都带逐键中文注释**：`config.yaml` 出厂即全注释；`setting.yaml` / `command.yaml` / `state.yaml` 在程序写盘时于**每个键上方**注入同款注释（`# 名称` + 作用范围 / 影响 / 取值范围），改值保存后注释仍在、解析正常。`functions` 列表项与 `monitor.layout` 映射条目按父路径套模板注释。导出的 `.bak` 与 `backup\` 快照**不注入注释**，保持单文件原样。

下面按文件给出 `command.yaml` / `setting.yaml` 的结构（`state.yaml` 由程序维护，不需手写）。示例为便于对照采用行尾紧凑注释，实际写盘是键上方注释：

```yaml
# ── command.yaml ────────────────────────────────────────────────
functions:                          # 功能扇区（顺序 = 扇形顺序）
  - name: "开记事本"                # ≤6 汉字 / 12 字母
    code: "cmd: start notepad"      # 前缀：无/py:（默认）/ cmd: / ps: / pwsh: / monitor:；可含成对标记【【【名】】】挂载 2~9 个次级项
    active: true                    # 勾选计扇形

# ── setting.yaml ────────────────────────────────────────────────
appearance:                         # 外观
  breath: true                      # 球体呼吸开关（false=颜色与大小全停，恒渲染起始色）
  color_start: "#FFFFFF"            # 起始色（十六进制）
  color_mid: "#FFFFFF"              # 过渡色（中段）
```

**采集周期两键的优先级**：`refresh_ms` / `idle_stop_sec` 的最终生效值 = `setting.yaml` 里你设过的值 > `config.yaml` 的 `collect` 组生效值（需 `enabled: true`）> 内置默认。这是迁移兼容特例——老版本里你在监视设置设过的周期，升级后继续生效、观感不变；从没设过的则可以用 `config.yaml` 调。保存监视设置时不会替你伪造这两个键，所以 `config.yaml` 的调参不会被挡住。

配置迁移：
* **老版本升级**：首次启动检测到旧版单文件 `setting.yaml`（无 `layout_version: 2`）时，先把全量快照落 `backup\pre_split_<时间戳>\setting.yaml`，再一次性拆成四文件并写 `layout_version: 2`；偏好、开关、坐标、布局全部原样保留。已迁移则不再重复动作。快照落盘失败就不迁移（保留原文件，绝不在无回滚点时改写你的配置）。
* **导入旧备份**：设置窗「导入/导出配置」支持备份与恢复；导入前落 `backup\pre_import_<时间戳>` 快照，且**不覆盖 `state.yaml`**——别人机器上的坐标/布局不会冲掉你当前的位置。
* 首次运行仍会自动扫描 exe 目录下的旧版 yaml 合并迁移；旧配置缺新键回退默认，旧字段（如 `idle_min`、旧独显固定键）自动换算升级。
* `backup\` 只保留最近 5 份程序自建快照，超出自动裁剪；你自己放进该目录的文件不受影响。

## 常见问题

Q：指令点击后没反应？
A：先确认指令格式无误（参考上文「指令格式」）；py 语法错误 / 指令为空的条目不会执行，扇区闪红光提示。可以在设置窗右键 → 高级编辑 →「测试」直接查看真实输出与错误信息。

Q：配置在哪里？换电脑怎么迁移？
A：配置都在 `%LOCALAPPDATA%\Aura_Pixie\` 目录里（四个 yaml：`config.yaml` / `command.yaml` / `setting.yaml` / `state.yaml`）。设置窗「导入/导出配置」→ 导出会把完整配置写成一个 `setting.yaml.bak` 到任意文件夹，新机器上「导入」即可迁移（导入不会覆盖你当前的球体坐标与窗格布局）；手动迁移则直接复制那四个 yaml 文件即可——`command\`（脚本缓存）与 `cache\`（运行缓存）是可再生的，不必带走。

Q：怎么开机自启动？
A：设置窗勾选「开机自启动」即可（注册「任务计划程序」项：登录触发 + 管理员权限，打包形态启动自愈自动重建）。

Q：为什么每次启动都弹 UAC？
A：程序需要管理员身份（资源监视的 CPU 温度/功耗/硬盘温度依赖内核驱动，自启计划任务也要最高权限）。不想被打扰的场合可用 `--no-elevate` 免提权运行，代价是温度/功耗/硬盘温度类读数不可用。

Q：监视窗格里温度/功耗显示「需要管理员」或无读数？
A：以管理员身份运行即可（正常双击 exe 会弹 UAC）。风扇转速在部分笔记本上 EC 不暴露给驱动，无读数属正常现象；独显功耗仅 NVIDIA 独显验证，AMD 适配尚未标定。

Q：球体不见了？
A：程序单实例运行，再启动一次会弹「本球在此」→ 点「在哪儿？」即可让运行中的球体红框闪烁定位。

Q：监视窗格重启后位置/组合会丢吗？
A：不会。位置与组合自动记忆，退出/关机立即落盘，重启自动恢复；若移动后立刻断电，最多丢失最后几秒的落盘窗口。

## 已知边界

* 弹窗定位与球体摆放目前只认主显示器（多屏且操作屏非主屏时可能偏移）；监视窗格已按光标所在屏适配。
* AMD 独显/核显的家族判定尚未真机标定，存在误判风险。
* 「显示缩放」的快捷启动单元尚未开发，配置值先保留。
